# Semantic News Novelty

**Semantic News Novelty** — сервис для аналитических агентств, которые работают с большим потоком новостных публикаций. Система группирует материалы в инфоповоды, находит повторы, выделяет значимые обновления сюжета и даёт семантический поиск без ручного чтения всей ленты. Проект не заменяет аналитика: он готовит структурированную основу для отбора материалов, проверки новизны и подготовки отраслевых отчётов. Runtime разворачивается через Docker Compose и включает UI, API, PostgreSQL/pgvector, RabbitMQ, ML-воркеры и мониторинг.

## О проекте

Аналитик получает десятки и сотни похожих публикаций по одному сюжету, но ценность обычно находится не в повторе, а в новом факте или развитии темы. Semantic News Novelty превращает поток публикаций в кластеры инфоповодов и помечает каждую публикацию как `significant`, `minor` или `duplicate`. Внутри используется BGE-M3 для эмбеддингов, графовая кластеризация с временными ограничениями и CatBoost-классификатор новизны по 18 previous-only признакам. Результаты доступны через Streamlit UI и HTTP API, а состояние обработки сохраняется в PostgreSQL.

`Semantic News Novelty` — публичное название продукта. `news-flow-analysis` — технический идентификатор репозитория.

## Что делает система

Основная целевая аудитория — небольшие и средние аналитические агентства, которые готовят отраслевые обзоры, тематические подборки и другие B2B-отчёты. Система устанавливается поверх источников и данных клиента и помогает быстрее перейти от сырой новостной ленты к экспертной интерпретации.

Основной сценарий:

```text
Источники клиента
        |
Импорт публикаций
        |
Кластеризация и дедупликация
        |
Оценка значимых обновлений
        |
Семантический поиск и ручная проверка
        |
Подготовка отчёта аналитиком
```

## Возможности

Система:

- импортирует публикации из файлов и через HTTP API;
- объединяет материалы об одном инфоповоде;
- выявляет дубли и близкие пересказы;
- отмечает значимые обновления внутри сюжета;
- поддерживает семантический поиск с сокращением повторов в выдаче;
- позволяет вручную проверить и скорректировать результаты;
- обрабатывает первичную загрузку в режиме `full` и новые поступления в режиме `incremental`;
- предоставляет демонстрационный UI и API для интеграции.

Результатом является не готовый аналитический отчёт, а структурированная основа для работы эксперта: кластеры инфоповодов, метки новизны, релевантные публикации и история развития сюжета.

## Границы продукта

Semantic News Novelty работает с уже собранным информационным потоком клиента. Проект не является системой сбора всех внешних источников, универсальным мониторингом информационного поля, инструментом автоматического фактчекинга или генератором готовых отчётов без участия аналитика.

Качество необходимо проверять на источниках и тематике конкретного клиента. Текущий технический результат основан на исследовательском датасете Lenta.ru и не является гарантией переноса на новый домен.

## Архитектура

```text
Пользователь / интеграция
        |
      nginx
   ----+----
   |       |
Streamlit FastAPI
           |
     ------+------
     |           |
 PostgreSQL   RabbitMQ
 + pgvector      |
     ^       model-service-vectorizer
     |       model-service-processor
     +-------------+
```

Компоненты:

| Компонент | Назначение |
|---|---|
| `ui` | Streamlit-интерфейс для входа, импорта, публикаций, ленты и поиска |
| `api` | FastAPI: пользователи, организации, новости, задачи, учёт операций |
| `model-service-vectorizer-*` | построение BGE-M3 embeddings на GPU или CPU |
| `model-service-processor` | кластеризация, novelty inference и сохранение результатов |
| `postgres` + `pgvector` | статьи, embeddings, pipeline state, поиск по векторам |
| `rabbitmq` | очередь фоновых задач обработки и поиска |
| `prometheus`, `grafana` | метрики API, очередей, pipeline job и Docker-ресурсов |

Подробнее: [архитектура](docs/architecture.md), [ML-пайплайн](docs/ml_pipeline.md), [HTTP API](docs/api.md).

## ML-пайплайн

Актуальная конфигурация:

- векторизация: `BAAI/bge-m3`;
- строгая графовая кластеризация с временным окном;
- консервативный второй проход присоединения к лучшему кластеру;
- CatBoost-классификатор новизны;
- разметка `significant`, `minor`, `duplicate`;
- работа в пакетном `full` и последовательном `incremental` режимах.

Первая публикация нового кластера получает `significant` по детерминированному правилу. Неоднозначные назначения помечаются для ручной проверки.

## Быстрый старт

Требования: Docker Desktop / Docker Engine с Compose. Рекомендуемый режим использует NVIDIA GPU; CPU-режим настраивается в `.env`.

```console
copy .env.example .env
docker compose up --build -d
docker compose ps
python scripts/demo_smoke_test.py
```

Для Linux/macOS первая команда:

```console
cp .env.example .env
```

`demo_smoke_test.py` проверяет демо-пользователей, публикации, pipeline job и семантический поиск. Успешный запуск заканчивается сообщением `Demo smoke test passed: ...`.

Первый запуск может занять несколько минут: Docker собирает образы, а model-service загружает BGE-M3 и прогревает кеш Hugging Face.

## Docker

Основной сценарий запуска:

```console
docker compose up --build -d
```

Полезные команды:

```console
docker compose ps
docker compose logs --tail=120 api ui model-service-processor
docker compose down
```

По умолчанию `.env.example` включает демонстрационный режим, одного GPU-векторизатора и одного CPU-процессора. Если GPU недоступен, установите:

```env
MODEL_SERVICE_VECTORIZER_GPU_REPLICAS=0
MODEL_SERVICE_VECTORIZER_CPU_REPLICAS=1
MODEL_SERVICE_PROCESSOR_REPLICAS=1
```

Сервисы публикуют наружу только пользовательские и диагностические точки входа: `NGINX_PORT`, `RABBITMQ_MANAGEMENT_PORT`, `GRAFANA_PORT`, `PROMETHEUS_PORT`. Внутренние API model-service доступны внутри Compose-сети.

## Переменные окружения

Файл [.env.example](.env.example) содержит рабочий локальный шаблон с комментариями к каждой переменной. Минимально перед запуском стоит поменять:

| Переменная | Зачем |
|---|---|
| `POSTGRES_PASSWORD` | пароль PostgreSQL |
| `RABBITMQ_PASSWORD` | пароль RabbitMQ |
| `PASSWORD_HASH_SECRET` | секретная добавка для хеширования паролей |
| `ACCESS_TOKEN_SECRET` | секрет для подписи токенов доступа |
| `GRAFANA_ADMIN_PASSWORD` | пароль администратора Grafana |

Ключевые настройки обработки:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `PIPELINE_CHUNK_SIZE` | `5000` | размер пачки для этапа векторизации |
| `PIPELINE_AGGREGATE_BATCH_SIZE` | `5000` | размер пачки для этапа агрегации |
| `PIPELINE_HISTORY_WINDOW_DAYS` | `30` | окно истории вокруг новых публикаций |
| `PIPELINE_BASE_STORY_THRESHOLD` | `0.82` | строгий порог baseline-кластеризации |
| `PIPELINE_ATTACH_MIN_SIMILARITY` | `0.75` | порог второго прохода attach |
| `NEWS_IMPORT_MAX_FILE_MIB` | `512` | максимальный размер файла импорта |
| `NEWS_IMPORT_MAX_ROWS` | `1000000` | максимальное число строк импорта |

## Метрики

Качество на текущем golden-наборе:

| Метрика | Результат |
|---|---:|
| Pairwise F1 кластеризации | **0.9017** |
| False merge rate | **1.89%** |
| F1 значимых обновлений | **0.9114** |
| Precision significant | **0.8471** |
| Recall significant | **0.9863** |
| MRR@10 семантического поиска | **0.9944** |
| Снижение повторов в Top-10 | **75.14%** |

Производительность:

| Сценарий | Режим | Время | Скорость |
|---|---|---:|---:|
| Docker Compose, прогретая модель, 10 000 публикаций | `full` | **226.33 с** | **44.18 публикации/с** |
| Холодное демо на 250 публикациях | `full` | **56.50 с** | **4.42 публикации/с** |

Эти результаты не являются production-гарантией: golden ограничен 121 публикацией, а перенос качества нужно проверять на данных конкретного аналитического агентства. Подробности: [оценка качества](docs/evaluation.md) и [бенчмарки](docs/benchmarks.md).

## Текущее состояние

Реализованы:

- импорт и жизненный цикл публикаций;
- асинхронный full/incremental pipeline;
- хранение BGE-M3 embeddings в pgvector;
- семантический поиск с дедупликацией по кластерам;
- роли, организации и учёт операций;
- Streamlit UI;
- GPU- и CPU-воркеры;
- тесты и CI.

Следующий этап — клиентский пилот на 300–500 публикациях: проверить перенос качества на источники клиента, оценить реальные поисковые запросы аналитиков, измерить сокращение времени подготовки отчёта и определить допустимый интервал полного reclustering.
